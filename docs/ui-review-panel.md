# 媒体面板交互复盘（三态互斥模型）

范围：`src/content/catcher.js` 里页面媒体面板的**折叠 / 展开 / 贴边**三种状态，以及承载它们的样式。
不含捕获规则本身——那部分见 [DOWNLOAD-STANDARDS.md](../DOWNLOAD-STANDARDS.md) 与 [DEVELOPMENT.md](../DEVELOPMENT.md)。

结论先说：这一轮的问题不是"某个像素没对齐"，而是**模型里有两套会贴边的东西**。把贴边收敛成只有胶囊能做之后，
一半的断言、一半的换算和全部的样式同步问题一起消失了。

模型落地后用户又报了两条，根因仍是同一类：**该由状态决定的东西被交给了元素自己**（2.9），以及
**该由指针决定的东西没有监听到指针**（2.10）。

再落地一次，又报了两条，还是同一族：**进入判据借用了"探出之后才占的位置"**，于是指针离边还几十像素
球就自己弹出来（2.11）；**脱离贴边时把"从哪条边来"丢了**，于是"贴边→打开→收起"这一串手势的最后一步
回不到贴边（2.12）。修这两条时夹具自己误报了一次——它在补间的第一帧量矩形（2.13）。

---

## 1. 最终模型

| 状态 | 可见的东西 | 内容 | 尺寸 | 进入方式 | 离开方式 |
| --- | --- | --- | --- | --- | --- |
| 折叠态 | 只有胶囊 | 下载图标 + 数量徽标 | 96×40（圆角胶囊） | 点面板内的收起图标 ⌄、点网页其他地方，或拖卡片到边上 | 点胶囊 |
| 展开态 | 只有卡片 | 标题栏（含 ⌄）+ 媒体列表 + 状态栏 | 326 宽，高 ≤ min(430, 80vh) | 点胶囊 | 点 ⌄、点网页其他地方，或拖卡片到边上 |
| 贴边态 | 只有沉进边缘的胶囊 | 只有图标（徽标收起） | 40×40 圆球，屏内露 30px | 把**胶囊**拖到边上；或从某条边上点开面板后再收起（吸回同一条边） | 指针落到屏内露出的那 30px 上 → 整颗滑出；点它 → 脱离贴边并展开 |

四条不变量：

1. **贴边的只有胶囊，展开的只有卡片**——任何时刻屏上不存在"半截卡片"。
2. **定位基准永远是胶囊的左上角**（`place = {left, top, dock}`），卡片是它的浮层，偏移量算出来，不单独存。
3. **状态切换只改尺寸与沉入量，不改原点**——所以收起/展开不会跳位。
4. **收起回到来路**：从哪条边点开的面板，收起就回到那条边（`dockResume`）；真拖动过就作废。

还有一条不属于几何、但同样硬的规则：**"探出与否"只由指针位置与静态矩形决定**。元素自己动不能改变
判定，否则一个手势会触发下一个手势；而那块"进入"矩形只能是**此刻真实可见的那一块**，不能是"探出之后
才会占的位置"，否则指针还没到边上球就自己弹出来了。

## 2. 这一轮出现过的问题与根因

按"看到的现象 → 真正的原因"排列。2.1–2.8 来自前几轮（用户报现象、截图与夹具定位根因），2.9–2.12 是
这一轮：四条都是用户直接报出的，其中 2.11、2.12 的根因正是 2.9、2.10 第一版修法留下的判据缺口。

### 2.1 贴边状态下折叠胶囊的图标显示不完整

现象：贴左边缘时只看到胶囊的一条白边，图标不见了；贴右边缘时 17px 的图标只露出 7px。

根因是**沉入方向与内容顺序读反了**。旧代码用 `translateX(calc(-100% + 20px))` 处理左贴边：
元素向左移动"自身宽度减 20"，留在屏内的是它的**右侧 20px**。而胶囊的内容顺序是
`padding-left 13 → 图标 17 → 间隙 8 → 徽标 22 → padding-right 13`，图标在**最左**，
正好整段落在屏外，留在屏内的是徽标。

> 结论：露出的那一条必须**大于等于**"从可见侧数到图标末端"的距离。新模型把胶囊收成 40px 圆球
> 并让图标居中，屏内 30px ≥ 球心 20px + 图标半宽 8.5px，四个方向共用同一条判据（`DOCK_PEEK`）。

### 2.2 卡片贴边时露出半截蓝色下载按钮

现象：把卡片拖到左边缘，屏内那 30px 里有一条行分隔线、半截圆角和半个蓝色下载按钮（截图 `c-card-docked-left.png`）。

根因：**卡片本身也会贴边**。卡片是 326px 的列表，任意一条 30px 竖切都会切到某一行；
这不是"切的位置不对"，而是"卡片不该被切"。新模型里卡片永远不沉入边缘，问题整体消失。

### 2.3 贴边把手与卡片/胶囊"看起来很割裂"

现象：为了统一，曾给卡片和胶囊各画一条 `.docked::after` 细把手，并用夹具断言两者的
`color / thickness / radius` 完全一致。

根因：**同一个视觉概念被实现了两遍**，然后靠测试去维持同步。样式一旦分叉，断言只能报警不能解释。
删掉把手元素后，"贴边"只剩一种长相（圆球），断言从"两处样式相等"变成"一处几何正确"。

### 2.4 最小化后胶囊跳位 / 展开面板被滚动条挡住

现象：点 ⌄ 之后胶囊出现在别处；展开的卡片右缘被 Windows 滚动条压住 15px。

根因两条：

- **基准在两种尺寸间切换**。旧模型 `place` 有时指卡片、有时指胶囊，最小化要做一次锚点换算，
  换算漏一步就是跳位。现在 `place` 只指胶囊，卡片偏移由 `applyCardAnchor()` 现算，不存在换算。
- **用了 `window.innerWidth/innerHeight`**。它包含 classic 滚动条轨道，Windows 的占位式细滚动条
  也照样占位（本机实测 `innerWidth - clientWidth = 15`）。改用 `document.documentElement.clientWidth/Height`。

### 2.5 拖动卡片时卡片瞬移（实测最多 256px）

现象：拖动过程中卡片忽然整块翻到另一侧。

根因：**"放不下就翻边"的锚点以指针位置为条件**。`place.top - (高度 + 间距) < 间距` 这类判断在拖动
的每一帧重算，越过阈值那一下方向就翻转。修法：横向只夹紧不翻转（夹紧已经保证完整可见，翻转是多余的）；
纵向的开合方向在展开时定下（`cardBelow`），**拖动期间冻结**（`if (!dragSession) …`）。

### 2.6 悬停滑出的胶囊有半截挂在视口外

现象（夹具实测）：右贴边圆球探出后，矩形是 `x=1329 → right=1425`，而可视宽只有 1369。

根因：夹紧边界用了 `panelLauncher.offsetWidth`——**补间过程中它是插值值**（40→96 之间），
于是按 40 算边界，把胶囊钉在了 `width - 40`。修法：夹紧按"当前该看得见的那一颗"取宽——
沉住时 `DOCK_SIZE`，悬浮或探出时 `PILL_FLOAT_W`（与 CSS 里 `.launcher { width }` 一致）。

### 2.7 折叠胶囊的内容横向不居中

现象：图标看起来偏左。实测胶囊内容左边界距 padding 13.9px、右边界 9.8px。

根因：左右内边距不对称（旧写法 `padding: 0 13px 0 13px` 配 `gap` 只作用于中间）。统一成
对称的 `padding: 0 var(--ndm-gap-md)` 后，`justify-content: center` 才真的居中；
夹具加了"图标中线 = 胶囊中线 ±1.5px"的断言。

### 2.8 一次工具链上的假故障

夹具里"点胶囊没能展开面板"连续两轮复现，最后定位到 CDP：`Input.dispatchMouseEvent` 的
`mousePressed/mouseReleased` **不带 `clickCount: 1` 时不会合成 click 事件**，鼠标按下抬起全部落地，
就是没有 click。另外，点贴边圆球必须**先悬停请它出来、等补间结束再按**：按下与抬起之间元素还在动，
Chrome 同样不合成 click（真实用户也是"移过去、等它出来、再点"）。

### 2.9 指针停在贴边附近，圆球无限弹出/收起

现象：把胶囊贴到边上后，鼠标移到靠近边界的地方，圆球就反复"滑出来—沉回去—滑出来…"，停不下来。

根因：**探出与否挂在胶囊自己的 `pointerenter/pointerleave` 上**。这两个事件的对像是"元素此刻的矩形"，
而探出这个动作恰恰会改这个矩形——`left`（贴边轴钉边，沉住时按 `DOCK_SIZE`、探出时按 `PILL_FLOAT_W`）、
`width`（96↔40）和 `transform`（沉入位移）三者同时补间 .22s。于是：探出 → 元素离开指针 → `pointerleave`
→ 收回 → 元素又回到指针下面 → `pointerenter` → 再探出。命中判定把自己当成了输入，形成自激振荡；
指针停在两种几何的差集里（球外、探出后的胶囊内）最容易触发，因为那正是"移动一下就换归属"的位置。

修法：**判定与元素解耦**。`hoverRects()` 只由 `place`、贴边方向和可视区算出两块矩形，window 上的
被动 `pointermove` 拿指针坐标对它求命中——矩形是状态的纯函数，元素怎么动都不改它们，振荡在结构上
就不可能了。配套两件事：

- **迟滞**：进出各一块矩形（见 2.11），探出→收回要彻底走出"探出后整颗胶囊"再放宽
  `HOVER_MARGIN`（8px）。中间这条带子让停在边界上 1px 的抖动不翻状态（没有迟滞的话，边界本身仍是翻转点）。
- **吸附/收回后解除武装**：`hoverArmed` 在拖拽松手吸附、以及收起重新贴边时置假，指针完全离开区域后才
  重新武装。松手点（或刚点过的收起图标）几乎总在刚创建的探出区里，不解除就会把用户刚"收下"的球立刻
  弹回来，看起来像没贴住。

> 结论：**hover 的对象是"由贴边状态算出的静态矩形"，不是"当前那颗球"**。至于这块矩形该有多大，
> 见 2.11——它决定的是"指针要多靠近边，球才理人"。

### 2.10 展开的面板挡住页面，点网页其他地方不收起

现象：面板展开后只能点标题栏的 ⌄ 才收回去；点页面别处它不动，用户以为面板"粘"在页面上。

根因：**外部点击的监听根本没有**。面板与提示各挂各的 shadow host（`ndm-media-panel-host` /
`ndm-toast-host`），`event.target` 跨 shadow 后是 host 本身或页面元素，只比 `target` 认不出
"这一下落在面板内部"；而挂在冒泡阶段的 `document` 上又会被页面自己的 `stopPropagation()` 吞掉。

修法：`document` **捕获阶段**的 `pointerdown`，用 `event.composedPath()` 判断归属——路径里有
`panelHost` 或 `toastHost` 就算内部（点 toast 不该顺手收起面板），否则 `setPanelCollapsed(true)`。
拖动中（`dragSession`）与非左键不触发，免得把拖到一半的手势当成"点外面"。

### 2.11 鼠标还没移到边上，胶囊就弹出了

现象：圆球贴在右边，指针离它还有几十像素、只是沿着右边那条"纵向带子"上下移动，球就滑出来了。
用户读到的不是"hover 到球"，而是"球自己跑出来挡路"。

根因：**2.9 的第一版判据把"探出之后"的那块矩形当成了进入条件**。沉住的球只有 30px 在屏内，而
`enter` 用的是 `PILL_FLOAT_W`（96）宽、以贴边轴钉在边上的矩形——它是"球一旦滑出来会占的位置"，
比球本身宽出 66px。于是指针落在屏内根本不存在的球上时判定就已经成立。迟滞带反过来又要求"走出整颗
胶囊"才收回，两块叠在一起等于把触发区放大了两倍。

修法：**进和出用不同的矩形**，各自对应"此刻真实可见的东西"和"此刻真实存在的东西"——

| 矩形 | 取值 | 含义 |
| --- | --- | --- |
| `enter` | 沉住时屏内露出的那一条：`DOCK_PEEK × DOCK_SIZE`（横贴边）/ `DOCK_SIZE × DOCK_PEEK`（纵贴边） | 指针要真的碰到球 |
| `keep` | 探出后整颗胶囊：`PILL_FLOAT_W × 高` | 球滑出来之后确实占着这块地方 |

两块外沿都再放宽 `HOVER_MARGIN`（8px）吸收边框与取整误差，于是 `keep \ enter` 就是迟滞带：在探出的
胶囊上逛不会收回，1px 抖动不翻状态，而"还没到边上"也不再弹出。代价是探出区不再比球大一圈——
点贴边圆球这件事改由"滑出来之后照常点整颗胶囊"承担，不存在"够不着"的问题（夹具怎么按它见 2.13）。

> 结论：**"hover 区比可见区大"是可以的，"hover 区比当前状态大"是不行的**。前者是给误差留余量，
> 后者是在替一个还没发生的状态做判据。

### 2.12 点开贴边胶囊再收起，胶囊不回边

现象：球贴在右边 → 指点它展开面板 → 点面板里的 ⌄（或点网页其他地方）收起 → 胶囊停在原地，
不再贴边。用户的手势是"贴边→打开→收起"，结果最后回到的是"浮动"，得重新拖一次才贴上。

根因：**脱离贴边这一步丢失了"我是从哪条边来的"**。点胶囊的处理器做的是一件必要的互斥操作
（贴边与展开不能同时成立，所以先 `releaseDock()` 再展开），但 `place.dock` 被清掉之后，
`setPanelCollapsed(true)` 只改尺寸，没有任何信息告诉它"收起后该吸回哪条边"。

修法：**`dockResume`**。点胶囊时把当时的 `place.dock` 记下来（任何真拖动都会清空它——用户已经把
球挪走了，不存在"回哪条边"），`setPanelCollapsed(true)` 发现 `dock` 为空而 `dockResume` 有值，
就把方向写回 `place`、`applyPlace()` 重贴边并 `savePlace()` 落盘，同时解除悬停武装（此刻指针正停在
刚形成的区域里）。⌄ 与"点网页其他地方"走的是同一个函数，两条路径自动一致。

> 结论：**状态切换要保住"来路"**。`place` 存的是几何，几何之外的意图（从哪条边来）需要一个显式字段，
> 不能靠"从当前几何猜"。

### 2.13 夹具自己也会"点空"：补间中的矩形与含位移的中心

现象：这一轮改完后夹具第 ⑦ 步（拖胶囊到左边缘）报"应吸附到左边缘：dock=right"，看起来像实现错了。

实测 dump 出来是：`docked` 已经是 `true`，但 `offsetWidth` 还是 96、`getBoundingClientRect()` 的 `x`
仍是脱离贴边时的值——也就是说这次读发生在收起后的**第一帧**，沉入的 `transform` 与 `width` 都还在 .22s
补间的起点。按这个矩形算出的"抓取点"落到了滚动条槽里，按下没命中胶囊，拖动根本没开始。

两条教训：

- **量之前先等补间走完**（`readPillAtRest()`：连续两次读到同一矩形才算数）。动画中途的矩形既不是沉住的
  形状也不是探出的形状，任何用它做的断言都不对应任何一种真实状态。
- **按之前先按可见的那一块**（`sliver` = 矩形与可视区的交集中心）。贴边元素的 `getBoundingClientRect()`
  **含沉入位移**，几何中心有一半在屏外；`clickSliver()` 因此是"移开 → 移到那一条上 → 等它出来 → 再按"，
  和真实用户的手势一致，而不是"对准中心硬点"。

> 结论：**夹具测的是"补间结束后的两个静止状态"**。中间态不是一种状态，因此也不该是一种断言对象。

## 3. 决策记录

| # | 决策 | 放弃的方案 | 理由 |
| --- | --- | --- | --- |
| D1 | 贴边只有胶囊 | 卡片也贴边（选项 A「一体式半隐入」） | 卡片被竖切必然出现半截行；两套沉入几何无法统一 |
| D2 | 拖卡片到边上 = 自动收起成贴边圆球 | 卡片贴边后仍是卡片 | 手势不变、结果唯一，展开/贴边互斥这条规则用户不需要记 |
| D3 | 定位基准只有胶囊原点 | `place` 兼作卡片/胶囊原点 | 消除锚点换算这一整类跳位 bug |
| D4 | 图标居中 + 露出 30px | 露出 20px 或给图标单独留白 | 30 ≥ 球心 20 + 图标半宽 8.5，四边同判据 |
| D5 | 吸附按"卡片 ∪ 胶囊"的并集 | 只按胶囊 | 卡片永远开在胶囊上方，只按胶囊则上下左右四条边只有两条能触发 |
| D6 | 横向只夹紧、纵向方向拖动中冻结 | 每帧重算翻转 | 消除拖动中的瞬移 |
| D7 | 胶囊用 `visibility` 让位 | `display: none` | `offsetWidth` 仍可测量，基准不漂；探出/夹紧需要这个宽度 |
| D8 | 样式统一为 `--ndm-*` 变量 | 每条规则各写各的颜色圆角 | 同一绿色曾出现 3 个十六进制值；暗色模式只能整片覆盖 |
| D9 | 探出判定 = 指针 × 静态区域（window `pointermove`） | 胶囊的 `pointerenter/pointerleave` | 元素自己会移动，用它自己的命中当输入就是自激振荡（2.9） |
| D10 | 进出两块阈值（`HOVER_MARGIN` 迟滞带）+ 吸附后解除武装 | 单一阈值、松手立刻判定 | 单阈值下边界本身就是翻转点；不解除武装则"拖到边上"会被松手点立刻撤销（进入条件的具体矩形由 D13 收紧） |
| D11 | 外部点击 = `document` 捕获阶段 + `composedPath()` | 冒泡阶段、比 `event.target` | 页面能 `stopPropagation()` 吞掉冒泡监听；跨 shadow 时 `target` 认不出内部 |
| D12 | 点 toast 不算"点外面" | 只豁免面板 host | Ctrl 跳过时提示正好浮在页面上，点它顺手把面板收走会让人找不到入口 |
| D13 | `enter` = 沉住时屏内露出的那一条，`keep` = 探出后整颗胶囊 | 两块都用探出后的胶囊（2.9 第一版） | 用"探出之后才占的位置"当进入条件，指针离边几十像素球就自己弹出来（2.11） |
| D14 | 收起吸回来时的边（`dockResume`） | 收起只改尺寸，留在脱离时的位置 | "贴边→打开→收起"是一个连续手势，最后停在浮动态等于把用户的第一步没收回去（2.12） |
| D15 | 真拖动即清空 `dockResume` | 一直保留最近一条边 | 拖动已经换了位置与意图，收起时再吸回老边缘是凭空多出来的行为 |

## 6. 夹具怎么锁住这个模型

场景 15（`node scripts/web-test.mjs --fixtures --filter 媒体面板`）用真鼠标走完十二个台阶，
每一步都是**双向**断言——该有的必须有，不该有的一条都不能多：

1. 折叠态：只有胶囊；图标与徽标都在；徽标有数字；胶囊右边 ≤ 可视宽；图标中线 = 胶囊中线 ±1.5px。
2. 点胶囊：卡片展开，且**胶囊不可见**（`visibility`），卡片四边完整落在不含滚动条的可视区内。
3. 点 ⌄：胶囊回来，且 `place` 原点**逐像素不变**（防跳位）。
4. 拖卡片到右边缘：自动收起 + 贴边；圆球 40×40；卡片不再占布局；屏内正好 30px；图标完整在 30px 内且居中。
5. 悬停圆球：整颗滑回屏内（四边都在可视区内）；指针移开：再沉回边上。
6. 点那一条：脱离贴边**并**展开（两个状态互斥）。
7. 拖胶囊到左边缘：同 4 的判据换成左侧。
8. 拖卡片到下边缘：同 4 的判据换成纵向。
9. 两块矩形逐点采样：落在"探出后才有"的那半截上 → **必须仍贴边**（这一条就是 2.11 的回归）；落在屏内
   露出的那一条上 → 探出；回到那半截 → 仍探出；原地 ±1px 抖动 5 次 → 恒定；走出整颗但仍在 8px 迟滞带内
   → 保持探出；彻底离开 → 收回；指针不动再连采 4 次 → 仍恒定。**判定的输入只有指针**，任何一次翻转都算
   失败（旧实现挂在元素自己的 `pointerenter/leave` 上，正是这一步会无限循环）。
10. 重新加载：`dock / left / top` 从 `chrome.storage` 恢复，而不是回到默认右下角。
11. 点击外部：点圆球展开卡片 → 点卡片内部**不**收回 → 点网页其他地方（可视区 25% × 25%）收回成胶囊、
    且**吸回下边缘**（`dock === 'bottom'`）→ 点那颗球仍能再展开。
12. 点 ⌄ 收起：同样回到下边缘，且钉住的底边与自由轴 `left` 和 10 恢复后的位置相差 ≤2px（2.12 的回归）。

全程 `count: [0, 0]`：这十二个界面手势一条消息都不许发。

配套的两条夹具规则是这一轮踩出来的，写在了 helper 里：**量之前先等补间走完**（`readPillAtRest()`，
沉入的 `transform` 与 `width` 各 tween .22s，中途读到的矩形既不是沉住的也不是探出的），**按之前先按
可见的那一块**（贴边圆球的 `getBoundingClientRect()` 含沉入位移，一半在屏外，抓几何中心会按到网页上）。

## 7. 已知取舍

- **卡片开在胶囊的上方/右对齐**，方向在展开时定下。把胶囊拖到很靠上的位置时，卡片会开在下方并夹紧，
  此时它可能与胶囊重叠——重叠无害（胶囊此时不可见），换来的是拖动中绝不瞬移。
- **`PILL_FLOAT_W` 是与 CSS 同步的常量**，改 `.launcher { width }` 必须同时改它，否则探出时的夹紧边界会错。
  注释里已写明这条耦合。
- 贴边时徽标收起（数量看不到）。这是刻意的：半截徽标比没有徽标更乱，而展开态第一行就能看到计数。
- **探出的目标就是那 30px，不是一整条带子**：指针要真的碰到沉住时露出的那一块，球才理人。代价是"贴边后
  不好点"没有靠放大 hover 区解决——它靠的是探出之后整颗胶囊照常可点（先碰到球 → 它滑出来 → 再点），
  与真实手势一致。换来的是"球不会在我还没过去的时候就弹出来挡路"。
- **收回比探出"钝"一圈**：探出后要把指针彻底走出整颗胶囊再放宽 8px 才收回。停在球与探出矩形的差集里
  不会翻转——迟滞的方向只有一个：进靠"碰到可见的那一条"，出靠"离开完整的那一颗"。
- **刚吸附/刚收回边上时悬停是解除武装的**：指针此刻就停在那块区域里，不解除会把用户刚收下的球立刻弹回去。
  要重新探出，指针得先离开该区域再回来（真实用户点完 ⌄ 本来就会挪手）。夹具的 `clickSliver()` 也是这么写的。
- **收起回边只在"没被拖动过"时成立**：`dockResume` 一旦被真拖动就清空，之后收起就停在原地，不会再吸回老边缘。
- **点击外部只作用于顶层文档**：面板只注入 top frame，iframe 内的 `pointerdown` 不会到这里，所以从框架里点
  页面不会收起面板（那里也看不见它）。弹出菜单里的开关走 `PANEL_STATE`，不受这条影响。
- 面板位置是**全局单值**（不区分站点、不区分左右手习惯）。多套位置属于 ROADMAP 的"永久不做"边界之外，
  但当前没有需求，不做。
